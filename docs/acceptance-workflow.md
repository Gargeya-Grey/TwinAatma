# Close the fixed acceptance gap

The [verification skill](../.agents/skills/verify-twinaatma/SKILL.md) owns the 54
outcomes, proof scopes, scorer bindings and final thresholds. They remain fixed.
Read [CURRENT](../outputs/handoffs/CURRENT.md) for the current version and decision.
The [28 October review](../work/gc-artifacts/.knowledgeos/strategy-adversarial-20261028/review.md)
explains these operational corrections.

## Select and bound the work

Choose an exact unresolved outcome or demonstrated safety regression. Classify
the work as product defect, stale/missing proof, verifier defect, or owner-held
gate. Name the missing evidence and existing driver. Unverified does not mean
absent. Local artifact work does not automatically require publication or models.

Keep one problem record across units: hypothesis, attempted candidates, decisions
and remaining work. A new folder, profile or reviewer does not reset that history.
After two non-admitted candidates under one premise, stop tuning it. Choose a
substantively different design or an independent critical gate. Another report
alone is not a reset.

Before execution, state what the result will change, its success/failure rule,
exact command, owned inputs, time/output budget and next action. A measurement
whose possible results do not change a decision is unnecessary. Reuse retained
evidence when its required bindings match. Preserve failed/inconclusive results.

## Separate construction from acceptance

| Unit purpose | Required result | Outcome credit |
|---|---|---|
| Mechanism experiment | Answers one bounded causal or feasibility question | None |
| Intermediate improvement | Correct behavior, material comparable gain, explicit regression limits and remaining work | None until a full outcome passes |
| Final verification | Complete mapped journey on the required scope/version | Existing scorer only |

Freeze the rule before execution. Never reinterpret or adopt an old rejected
candidate. Future correct intermediate gains may remain above a final latency
limit if their declared improvement/regression rules pass. Final resource
acceptance still requires every approved limit. One sample or fewer calls does
not establish a reliable speedup.

A candidate gets one cheap triage and at most one declared complete comparison.
Incorrectness rejects it. An inconclusive comparison ends that attempt. Repeated
comparisons need matched realistic workloads, alternating observations, complete
errors/distributions and a difference larger than noise. Keep instrumented and
uninstrumented results separate. Label estimates; they are not measured savings.

Before selecting an architecture, account for all affected public operations,
preserved/unknown costs, startup, memory, packaging and supported runtimes.
Compare at most two viable alternatives with the current implementation as a
reference. A hot region does not prove its replacement can meet the whole budget.
Preserve product invariants; distinguish them from current call boundaries,
representations and language choices. Changed observation timing or formats need
explicit equivalence and migration proof.

## Reuse qualified execution

Use canonical drivers and qualified launch modes. Add a helper only for a named
missing capability; prefer an observation adapter to another controller. Inspect
real input metadata before assuming its shape. A discarded verifier anomaly
blocks only work depending on it, not the entire product plan.

Qualify a changed subprocess mode with a tiny zero-note control. Retain actual
member identities and stopped states; do not guess process counts. Reusing an
observer does not qualify new flags. An unchanged qualified mode needs no repeat
qualification. Preserve the original failed criterion; do not relax it afterward.

Preserve the complete qualified launch: executable, arguments, working directory,
environment and user identity. The same interpreter under a different WSL user
is not the same execution context. Read the recorded command before reusing it;
do not reconstruct it from a summary that omits flags.

Qualify full-suite environments before long runs. Copies may omit build/CI/report
inputs, and extra Windows path depth can break fixtures. After setup failure,
classify all families and pass original-form representatives before a full retry.
Adapted fixtures are not original-form proof. A preserved reviewed patch may be
applied provisionally to the normal uncommitted checkout; application is not proof.

## Stabilize, freeze, then refresh acceptance

Prove focused adverse behavior and obtain one independent review before expensive
proof. A reproduced finding requires a new version. Never edit live run inputs.
Wait on the original handle, consume completion once, and retain exits/shutdown.

After the planned product changes stabilize, select one exact freeze for the
native suite, applicable source families, formal resource distributions and
installed matrix. Refresh only invalidated applicable proof. Existing complete
product/producer bindings govern reuse; never narrow them manually. Avoid package
rebuilds and genuine-host repetitions between unsettled edits.

For PORT.measured_resource_budget, use the canonical post-setup workload at 100,
1,000 and 10,000 notes: startup p95 ≤5s; capture/recall p95 ≤2s; peak RAM ≤256MiB;
context ≤16KiB. Retain at least 20 cold starts, 20 warm starts, 20 recalls and
20 captures per scale with complete distributions. Exclude model time; do not
flush OS caches. An aged-rebuild experiment is not this formal workload.

Combine compatible current reports into the fixed 54-row grade. Report verified
and unresolved counts/percentages, new/lost-proof IDs, critical vetoes, version
and scope. Distinguish defect closure, proof coverage and comparable resource
distance. Full product loss is unresolved/54 only for a cumulative comparable
grade; otherwise it is unknown. Partial 15/54 versus historical broader 41/54
does not establish capability loss. A new counterexample holds an earlier PASS
until repaired. Expected memory wrap-up changes make a packet time-bound, not
a reason for endless regrading.

## Handoff and actual authority

Finish a unit before starting another. Update CURRENT with one next decision
and links to dated receipts. Historical commands/grants are records, not active
instructions. Register actual created evidence with the shared observer. If
restricted, retain a local inventory/error/receipt and continue product work.
No bypass, collection or deletion follows from completion. Preserve unknown
ownership and active evidence.

Local reversible source/package preparation is within the engineering task.
Commits, pushes, CI and genuine model calls need their exact current authority;
prepare the concrete version/payload before asking. Clean-device restore uses
the approved two fresh Windows CI runners; a second physical laptop is not
required. Model batches use reviewed payloads and single-use claims, no retries.

Keep owner-terminal approval and representative use pending as requested. Only
the owner can approve identity. Representative-week proof needs actual elapsed
use, at least 20 useful conversations and the other contract conditions.
Synthetic trials cannot substitute. Do not reopen settled policy/budget choices.
