# Synthetic longitudinal learning

Run `longitudinal.py` to observe the fixed `LEARNING.semantic_drift` and
`LEARNING.rejection_recurrence` outcomes through public CLI and MCP processes.
The literal case plan is separate from the producer and independently duplicated
in the scoring helper. It is retained before any product invocation.

```powershell
python -B -X utf8 .agents/skills/verify-twinaatma/scripts/longitudinal.py --output work/gc-artifacts/.knowledgeos/longitudinal
python -B -X utf8 .agents/skills/verify-twinaatma/scripts/longitudinal_adapter.py <printed-report.json> --output <fresh-contained-score.json>
```

There are 27 literal cases. Three exercise activity-only initial, reformatted and
retimestamped sources through ordinary session start/end calls. Nine reject
insufficient, pending, incomplete, duplicate, copied, unchanged, mismatching,
contradictory and superseded evidence. The positive sequence reviews pending
decisions through the public CLI, records explicit paired belief statements
through MCP, and checks the actual restarted source hashes and outcome receipts.
Two completed sources must retain distinct IDs, paths and concrete narratives.
The proposal must name both before and after statements, cite the actual sources
and narratives, and remain explicitly uncertain and unapproved.

The recurrence sequence rejects the signed proposal through public MCP. Both
drift and lesson entry points must suppress old evidence across process restarts,
formatting, timestamps, renames, rekeys and copied narratives. A missing or
inconsistent signed history must refuse. A genuinely new reviewed completed
source can create a new named draft, while old evidence remains rejected.

The cadence state is a declared synthetic fixture. It does not establish a week
of actual host behavior, ordinary host usefulness, independent verification of
the reported outcomes, or independent human consent. No approval entry point is
called, and the owner identity must remain byte-for-byte unchanged.

`longitudinal_adapter.score` independently reads retained source text, exact
public requests and original responses. It verifies complete current product and
producer/support manifests, outcome receipt hashes, signed-history HMACs, literal
proposal text, real-vault sentinel hashes, and complete physical fixture inventories.
Each invocation has a role, instance, parent, PID and a nonoverlapping lifetime.
Sequential OS PID reuse is allowed; reused instances and overlapping or missing
process bindings refuse. This producer launches no nested product processes. Any
unexpected or unstopped nested process prevents credit.

The combined scorer accepts `--longitudinal-report` only with scope
`longitudinal`. It can award the two named fixed outcomes. Source proof cannot
award host, installed-artifact or owner-consent outcomes. The denominator remains
54. Keep every failed native attempt and failed scoring attempt. A grader-only
correction may re-evaluate unchanged retained observations, with original and
current grader hashes reported separately.
