# Set up once and keep working

The person completes setup once, then memory is available from ordinary conversations. Their notes remain usable when they move or restore them.

## Sub-features

- SETUP.1. A clean supported install initializes a usable vault with honest exit status.
- SETUP.2. Host discovery and the first meaningful chat use the intended memory.
- SETUP.3. Reconfiguration and upgrades preserve existing configuration and custom content.
- PORT.1. Same-device moves and clean-device restores have explicit, tested semantics.
- PORT.2. Missing approval keys or divergent device state fail visibly without corrupting identity.

## How to get to it (user POV)

Install a wheel or binary, run `twinaatma init`, then `twinaatma setup-host`. Start a normal conversation in each advertised host. Move or restore the vault through its supported procedure.

## Driving it with CLI and host traces

Preconditions: use a fresh task-owned directory, the exact artifact under review, and a separate host profile.

- Source initialization. Run the core driver from SKILL.md. Require successful post-init rebuild and validation, a real Self file, and usable memory calls.
- Installed distribution and host. Follow [the retained installed-package recipe](../references/installed-packages.md): build exact candidates, install in neutral environments, check the Windows/Linux wheel/executable matrix, then drive actual Windows Codex conversations through each installed launcher. Retain full assets, packaging inputs, dependencies and independent current-source bindings.
- Frozen host batch. Follow [the single-batch recipe](../references/host-batch.md) to prepare a sealed inventory with zero model calls. A bound human authorization permits the three installed-wheel, three installed-binary and three advanced-source conversations once. The launch guard rechecks the complete source inventory and authorization before each conversation. Preparation and synthetic corruption controls award no host acceptance credit.
- Distribution. Build an artifact to a task-owned output. Run `python -B tests/package_smoke.py --wheel <actual-wheel> --source .` or `--binary <actual-executable>`. Retain its hash and isolated-import evidence. Follow [the real-runtime hook recipe](../references/runtime-hooks.md) to run both generated commands under every current supported minor, without PATH activation and with poisoned imports. The source driver's Python 3.11 requirement does not change the package's Python 3.9 promise.
- Codex CLI. Run the host driver from SKILL.md. Generated setup must mark its memory server required so the first turn waits for initialization; preserve foreign servers' startup policy. A delayed-start diagnostic earns no normal installed-host credit. It creates native project TOML, discovers tools through the genuine host, and retains actual wire/tool/final-answer evidence across three conversations. Existing config merging preserves foreign text or refuses unsupported layouts. Older interpreters without tomllib refuse existing TOML merges.
- Other hosts. Run `twinaatma setup-host --host cursor --vault <fixture> --write` inside the isolated profile. Start a meaningful chat. Capture tool discovery and the actual first memory call. Repeat equivalent advertised host entry points. A printed config is insufficient.
- Preservation. The core journey executes valid, malformed and wrong-shaped configurations for Cursor, VS Code and Codex, preserving foreign settings and recording exact refusal bytes. Seed the fixture host config with another server, custom fields, malformed JSON, and a wrong-shaped server collection in separate cases. Record bytes before setup. Require safe merge for valid configs and preservation plus an actionable failure for unreadable configs.
- Honest failure. Obstruct initialization storage in a task-owned fixture. Require a nonzero exit and accurate partial-state report when required setup steps fail.
- Same-device move. Follow [native installed relocation](../references/installed-native-move.md) with both current Windows artifacts. Keep generated configuration bytes unchanged. Require original notes, IDs, relative links and recall before the move, while the old path is absent, and after a distinct unrelated vault reuses that path. The unrelated vault must remain untouched. Duplicate visible roots with the bound ID must refuse.
- Resource budget. Run `python -B .agents/skills/verify-twinaatma/scripts/resource_budget.py --output work/gc-artifacts/.knowledgeos/resource-budget/run` on the approved Windows device while other verification work is stopped. It retains 20 cold starts, 20 warm restarts, 20 recalls and 20 captures at each of 100, 1,000 and 10,000 notes. One untimed public startup establishes a complete indexed and signed setup after generating the notes. Cold samples use fresh processes after restoring that complete baseline, including external signing and session state. Warm samples also use fresh processes but retain the initialized state between calls. Neither group flushes the operating system's file cache. Pass its report to `acceptance.py --extension-report resource-budget=<report.json>`. The adapter recomputes latency, context bytes and process memory from distinct retained requests and native counters, and verifies the baseline and each cold sample's binding. A completed producer run is not a budget pass. Missing coverage stays unverified, and any budget breach is FAIL.
- Upgrade and divergence. Build the old wheel from `e831fdc` (that revision has no packaging, so add a minimal `pyproject.toml` and `setup.py` to its `git archive` extraction and run `pip wheel --no-deps --no-build-isolation`). Install the current wheel and executable with `artifact.py`, then run `python -X utf8 -B scripts/upgrade_divergence.py --artifact-report <wheel-report> --artifact-report <binary-report> --old-wheel <old.whl> --output work/gc-artifacts/.knowledgeos/upgrade/report` on native Windows. It upgrades one environment in place, drives two vault copies with separate state directories through a simulated sync with a conflict copy, and observes each approval in a hidden console only up to its refusal or prompt. It never answers a prompt. Score it with `acceptance.py --extension-report upgrade-divergence=<report.json>`; `upgrade_divergence_adapter.py` recomputes all 23 cases. The owner's device-local policy (21 October 2026) is the expectation, so a missing doctor flag or hint stays a FAIL.
- Restore. Restore a separate copy on a clean device. Verify notes, links, identity, retrieval, host wiring, and pending-proposal behavior. Retain both originals. When approval state cannot transfer, report the limitation and require a fresh proposal instead of silently accepting the old one.
- Missing signing state. For the Windows wheel and executable, run `python -B .agents/skills/verify-twinaatma/scripts/signing_state.py --artifact-report <artifact report.json> --output work/gc-artifacts/.knowledgeos/signing/<cell>`. Each run creates pending proposals through MCP, backs up and removes the key and binding files of the isolated state, then retains memory use, a hidden-console approval refusal (stdin and stdout on the console, stderr redirected, no answer ever sent), doctor output, a proposal made after the loss and the restore from backup. Score both reports with repeated `acceptance.py --extension-report signing-state=<report.json>`; one cell earns no credit. The refusal must explain itself and give a recovery hint, and doctor must name the lost key; a pending proposal is judged by the ledger, listings and doctor, never by approving it.
- Clean-device restore (CI). The laptop is one device, so a restore on a clean machine needs two fresh GitHub-hosted Windows runners. Push to `acceptance/**` or start `.github/workflows/clean-device-restore.yml`. Job `origin` (device A) installs this commit's wheel and executable, makes a synthetic vault with linked notes, stable IDs and one signed pending proposal, and uploads the two backups a person carries: the vault folder, and separately the off-vault signing state. Job `restore` (device B, another fresh runner) installs the same commit, unpacks the vault, drops the index, runs `setup-host --host codex --write` and `doctor`, and drives the exact configured MCP command (`initialize`, `tools/list`, `memory_session_start`, search, related) with no model call and no credential. Without the signing-state backup the old proposal must be refused in a hidden console before any prompt, with a hint to propose again; after the backup is restored it must be valid again at describe time (`self pending`, the MCP listing and `doctor`). An approval answer is never sent. Download the `clean-restore-bundle` artifact into `work/gc-artifacts/.knowledgeos/clean-restore/ci-<run>/` and score it with `acceptance.py --extension-report clean-restore=<bundle>`; `clean_restore_adapter.py` checks the attestation and the bindings. The owner's device-local policy (21 October 2026) is the expectation, so a missing doctor message or hint stays a FAIL. Require `doctor` to exit zero after the signing-state backup is restored. Reconnection must update the generator-owned Cursor files using their recorded hashes; custom files remain preserved. The grader distinguishes these operational files and their receipt from source notes, identity, vault ID and custom configuration.

## Gotchas

Doctor checks local files and index health. Current generated MCP configurations bind the full vault ID, omit a fixed working directory and retain an absolute fallback. A matching vault in the host working-directory ancestry takes precedence; an unrelated fallback or conflicting visible copies refuse. Markerless legacy launchers keep their previous absolute semantics. Cursor hooks use absolute paths. `setup-host --write` reconnects files whose hashes match the ownership record made by `init`; legacy or edited hooks that need replacement are preserved and refused with a diagnostic. Pending approvals depend on off-vault signing state. A Windows MCP move does not establish other-host hooks, clean-device restore or approval-state transfer.

## Journey fixes (21 October 2026)

- Doctor says in plain words when ledger rows were signed by a different key (key lost or replaced, or a ledger from another device or install), that those proposals cannot be approved here, and how to recover; it no longer prints the healthy "signed" line when no row verifies.
- Doctor prints the installed version, the vault's declared schema and a compatibility verdict; `vault_version_check` orders a dev build before its release and returns None for a compatible vault.
- `twinaatma validate` exempts a vault-root `README.md` guide only when it has no frontmatter. A root README with a metadata block and every README inside a note folder are validated as notes.
- Doctor warns, on every device, about sync conflict copies (Syncthing, Dropbox, Nextcloud names) and notes that share an `id:`; it never renames, merges or rewrites either copy.
